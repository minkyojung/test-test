# 에어비앤비 클론 페이지 설계

## 현재 코드베이스에서 확인한 점

저장소에는 현재 `README.md`와 스펙 문서만 있고, 애플리케이션 코드, 빌드 설정, 테스트 설정이 없다. 따라서 이 설계는 기존 화면을 수정하는 방식이 아니라, 새 프론트엔드 앱의 최소 구조를 추가하는 방식으로 요구사항을 만족한다. 따라야 할 기존 UI/테스트 패턴이 없으므로, 구현에는 작은 단일 페이지 정적 앱 구조를 새로 만든다.

## 접근 방식

정적 프론트엔드 앱을 저장소 루트에 추가한다. `index.html`, `styles.css`, `src/main.js`를 중심으로 앱을 구성하고, 브라우저에서 바로 열 수 있는 단일 페이지 데모로 만든다.

페이지는 세 가지 주요 상태를 가진다.

1. 목록 상태: 상단 히어로/브랜드 영역, 검색 영역, 숙소 카드 그리드를 표시한다.
2. 필터 결과 상태: 검색어, 날짜, 인원 조건에 따라 숙소 목록을 다시 계산해 표시한다.
3. 상세 상태: 선택한 숙소의 상세 패널 또는 상세 섹션을 표시하고 목록으로 돌아갈 수 있게 한다.

숙소 데이터는 실제 API가 아니라 `src/main.js` 안의 고정 샘플 데이터로 시작한다. 각 숙소는 `id`, `title`, `location`, `price`, `rating`, `image`, `description`, `amenities`, `capacity`, `availableDates` 같은 필드를 가진다. 이렇게 하면 백엔드 없이도 목록, 검색, 빈 결과, 상세, 없는 상세 상태를 모두 재현할 수 있다.

## 화면 구성

- 상단 영역: 서비스 이름, 짧은 소개 문구, 여행 탐색을 유도하는 문구를 표시한다.
- 검색 영역: 목적지/검색어 입력, 날짜 입력, 인원 선택, 초기화 버튼을 둔다.
- 숙소 목록: 반응형 카드 그리드로 표시한다. 각 카드에는 이미지, 위치/이름, 가격, 평점이 들어간다.
- 빈 상태: 필터 결과가 없거나 숙소 데이터가 비어 있을 때 같은 빈 상태 컴포넌트/마크업을 사용한다.
- 상세 영역: 카드 선택 시 같은 페이지 안에서 선택 숙소의 큰 이미지, 설명, 편의 정보, 가격/평점, 뒤로 가기 버튼을 표시한다.
- 없는 상세 상태: URL 해시나 내부 상태가 존재하지 않는 숙소 id를 가리키면 상세 대신 찾을 수 없다는 메시지와 목록으로 돌아가기 동작을 표시한다.

## 반응형 UI

CSS는 모바일 우선으로 작성한다. 작은 화면에서는 검색 필드와 숙소 카드가 한 열로 쌓이고, 넓은 화면에서는 검색 영역과 카드 그리드가 여러 열로 확장된다. 주요 텍스트와 카드 정보가 잘리지 않도록 고정 너비 대신 유동 너비와 `minmax` 기반 그리드를 사용한다.

## 상태와 동작

`src/main.js`는 다음 책임을 가진다.

- 샘플 숙소 데이터를 보관한다.
- 현재 검색어, 날짜, 인원, 선택된 숙소 id 상태를 관리한다.
- 조건 변경 이벤트를 받아 숙소 목록을 다시 렌더링한다.
- 카드 선택 시 상세 상태를 렌더링한다.
- 뒤로 가기 또는 목록 보기 동작으로 상세 상태를 해제한다.
- 존재하지 않는 상세 id가 선택되면 오류를 던지지 않고 찾을 수 없음 상태를 렌더링한다.

## 테스트와 확인 방법

현재 저장소에는 테스트 프레임워크가 없다. 새 빌드/테스트 도구를 도입하지 않고, 구현 후에는 브라우저에서 직접 확인 가능한 정적 페이지로 검증한다. 필터링처럼 순수 함수로 분리할 수 있는 로직은 `src/main.js` 안에서 별도 함수로 두어 추후 테스트 프레임워크를 도입할 때 쉽게 검증할 수 있게 한다.

수동 확인 항목은 다음과 같다.

- 페이지 최초 진입 시 상단, 검색 영역, 숙소 카드 목록이 보이는지 확인한다.
- 숙소 카드마다 이미지, 이름/위치, 가격, 평점이 보이는지 확인한다.
- 검색어, 날짜, 인원을 변경했을 때 목록이 바뀌는지 확인한다.
- 결과가 없는 조건에서 빈 상태 메시지가 보이는지 확인한다.
- 카드를 선택하면 상세 정보가 보이고, 뒤로 가기로 목록에 돌아오는지 확인한다.
- 존재하지 않는 상세 id 상태가 되어도 화면이 멈추지 않고 찾을 수 없음 메시지가 보이는지 확인한다.
- 모바일 폭과 데스크톱 폭에서 주요 정보가 잘리지 않는지 확인한다.

## Decisions

- 단일 페이지 정적 데모로 만든다 — 여러 페이지 앱이나 백엔드가 있는 앱도 가능하지만, 요구사항의 `Decisions for You`에서 기본 가정한 범위가 단일 페이지 데모이고 현재 저장소가 비어 있어 가장 작게 완성 여부를 확인할 수 있다.
- 실제 에어비앤비 브랜드 복제 대신 에어비앤비에서 영감을 받은 독자적 UI로 만든다 — 실제 브랜드 자산을 그대로 복제하면 범위와 권리 문제가 커질 수 있고, 요구사항의 Out of Scope에도 실제 브랜드 자산 복제가 제외되어 있다.
- 샘플 데이터는 클라이언트 코드 안에 둔다 — JSON 파일이나 API 형태도 가능하지만, 현재 목표가 실제 데이터 연동이 아닌 화면/상호작용 데모라서 파일 수와 실행 조건을 줄인다.
- 테스트 프레임워크는 도입하지 않는다 — 자동 테스트를 추가할 수도 있지만, 현재 저장소에는 패키지/빌드/테스트 패턴이 전혀 없어 도구 선택 자체가 별도 결정이 된다. 이번 설계에서는 브라우저 수동 확인으로 요구사항을 검증하고, 필터 로직은 나중에 테스트 가능하도록 함수로 분리한다.

## Requirements Met

- 1.1 — `index.html`의 상단 영역, 검색 영역, 숙소 목록 영역과 `src/main.js`의 최초 목록 렌더링이 충족한다.
- 1.2 — 샘플 숙소 데이터의 이미지, 이름/위치, 가격, 평점 필드와 카드 렌더링이 충족한다.
- 1.3 — 숙소 배열이 비어 있거나 렌더링할 결과가 없을 때 빈 상태 마크업을 표시하는 목록 렌더링이 충족한다.
- 1.4 — `styles.css`의 모바일 우선 레이아웃과 반응형 카드 그리드가 충족한다.
- 2.1 — 검색어 입력 이벤트와 숙소 위치/이름/설명 기준 필터링 함수가 충족한다.
- 2.2 — 날짜 입력과 인원 선택 UI, 그리고 날짜/수용 인원 기준 필터링이 충족한다.
- 2.3 — 필터 결과가 0개일 때 빈 결과 메시지를 표시하는 렌더링이 충족한다.
- 2.4 — 조건 입력 변경 이벤트가 현재 필터 상태를 갱신하고 목록을 다시 렌더링하는 흐름이 충족한다.
- 3.1 — 숙소 카드 클릭 이벤트가 선택 숙소 상세 상태를 렌더링하는 흐름이 충족한다.
- 3.2 — 상세 영역의 설명, 편의 정보, 가격/평점 표시가 충족한다.
- 3.3 — 상세 영역의 목록으로 돌아가기 버튼이 선택 상태를 해제하고 목록을 다시 보여주는 흐름이 충족한다.
- 3.4 — 존재하지 않는 숙소 id를 상세 상태로 렌더링하려 할 때 찾을 수 없음 메시지를 표시하는 분기가 충족한다.
